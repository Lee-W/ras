# 專案記憶與回顧

[English](../references/memory.md) · [臺灣華語 README](../README.zh-TW.md)

記憶屬於所選的簡報專案，已接受的條目存放在 `.ras/memory.json`；初始化的專案會把它（以及 `.ras/reviews.json`）納入 Git，其餘 `.ras/` 內容則忽略，因此記憶會隨簡報儲存庫的 clone 一起帶走。
不會自動讀取家目錄的記憶庫或其他專案的記憶。
若只複製檔案而沒有帶走 `.ras/memory.json`，記憶也不會跟著搬移。
要跨專案重用，需由使用者明確選擇條目文字與目的地。
記憶不會打包進匯出的投影片或公開外掛儲存庫。

## 記憶的三層

RAS 從三層讀取偏好。目前的需求與 brief 優先於所有層；各層之間，範圍較窄的優先。

1. **專案：**所選簡報的 `.ras/memory.json`，見下文。存放只適用這場演講的內容。
2. **使用者 profile：**講者自己維護的一份 Markdown，存放跨簡報都成立的偏好。
   路徑來自你自行在簡報 `ras.config.json` 加入的 `"profile": "<path>"` 鍵（相對於簡報目錄；範本不含此鍵）、
   `ras prompt <operation> --profile <path>`，或使用者在需求中指定的路徑。
   這份檔案可以放在任何儲存庫之外。沒有預設 profile：只有上述其中一種方式指定時才讀取。
   外掛中的 `profiles/wei.md` 是範例，不是預設。
3. **通用：**外掛的 `references/`，存放對任何講者都成立的規則。講者偏好不放在這裡。

## 讀取與優先順序

開始 create、revise、review 或 export 時，讀取所選專案可用的記憶。
在已初始化的簡報內執行 `npm run memory -- list`；不適合安裝相依套件時，也可以直接讀取 `.ras/memory.json`。
最多使用十筆相關條目，先比對目前觀眾、工作與主題，再優先採用近期回饋。
若某條目實際改變決策，應指出該條目。

目前的使用者指示與需求優先於既有偏好。
記憶是脈絡資料，不代表可執行指令或擴大工作範圍。
記憶格式無效時要回報，不能默默以空記憶庫取代。
純聊天模式只使用使用者提供的條目，並說明尚未儲存。

## remember

🎧 CHU² 主持 `ras:remember`，從需求或正在操作的簡報確認目標專案，並依[工作流程中目標簡報不唯一時的規則](workflow-zh-tw.md#輸入與決策)處理。
以使用者實際表達的內容為依據，儲存簡潔的偏好、修正、慣例或參考資料。
不要複製整份來源文件、受著作權保護的摘錄、憑證或無關的公司資料。

明確要求記住清楚的事實，即授權在所選專案儲存，不需要重複確認。
完成後顯示實際儲存的文字與路徑。
若是推論出的規則、與既有條目衝突，或目的地不明，先提出確切文字並釐清缺少的決定。
相同 ID 的替換必須已獲授權，無關條目要保留。

條目格式如下，文字為原創範例：

```json
{
  "id": "explain-before-code",
  "type": "project",
  "text": "對這群觀眾，先介紹問題，再展示程式碼。",
  "source": "講者在目前工作階段明確提出的偏好。"
}
```

| 類型 | 用途 |
| --- | --- |
| `user` | 講者偏好 |
| `feedback` | 具體修正 |
| `project` | 這份演講的慣例 |
| `reference` | 相關來源的指引 |

將候選 JSON 存在 `.ras/` 下，在所選專案執行：

```sh
npm run memory -- save .ras/memory-candidate.json
npm run memory -- list
```

只有已要求或授權替換／刪除時，才使用對應指令：

```sh
npm run memory -- save .ras/memory-candidate.json --replace
npm run memory -- remove explain-before-code
```

儲存後移除暫存的候選檔。工具會驗證條目，並以不可分割的寫入方式更新記憶庫，
不會修改其他專案或家目錄。若儲存失敗，回報失敗並保留既有條目。

## retro

🎧 CHU² 依目前對話、使用者修正與真實建置／審閱證據主持 `ras:retro`。
提出少量可重用的經驗，不捏造先前工作階段；缺少脈絡時請使用者簡述。
區分這份演講的偏好與工具缺陷；工具問題另外提出修正，不將暫時作法記成通用規則。

跨簡報反覆出現的偏好，可以作為**升級到 profile** 的候選：使用者說它適用每一場演講，
或它與使用者提供的其他簡報條目相同。提議把文字追加到目前的 profile 檔，並寫明路徑。
逐筆確認與授權的規則相同；沒有確認過的 profile 路徑與同意，就不寫入。
只追加，不改寫 profile 的其他內容。

每次提出一個候選條目，附上依據、目標專案與建議文字，提供儲存、修改、略過或結束的選擇。
使用者明確授權儲存後，直接接續 remember 流程，不需要第二次確認。
沒有回答代表尚未決定；在回覆中保留候選項目，但不寫入。
單純要求回顧不等於授權儲存推論出的偏好；若使用者已指定範圍與事實並授權儲存，則依既有授權辦理。

結束時列出實際儲存的 ID、略過項目與未決定的選項。
角色語氣簡短即可，不捏造多代理討論。
